# Deploying to Render's free tier

No credit card. Public HTTPS URL. About 15 minutes.

This is the fallback, and it costs something real — read the trade before you
start.

## Why this and not somewhere better

Checked September 2026:

| Host | Card? | RAM | Verdict |
|---|---|---|---|
| Oracle Always Free | **required** | 24 GB | Out — card needed to verify identity |
| Fly.io | **required** | — | Out — free tier ended, 2-hour trial only |
| Railway / Google Cloud | **required** | — | Out |
| HF Spaces (Docker) | no | 16 GB | **Out — Docker SDK requires PRO.** Only Static Spaces are free, and those cannot run Python |
| Koyeb | sometimes | 512 MB | Possible; may demand a card to prove you are human |
| **Render** | **no** | **512 MB** | This guide |

Tunnelling from your own machine was also tried and is blocked: the corporate
network's Forcepoint filter returns an HTML block page for
`api.trycloudflare.com`, so `cloudflared` cannot create a quick tunnel. ngrok and
similar will fail the same way.

## What 512 MB costs

The full dependency set is 1,279 MB installed and needs roughly 700 MB resident,
almost all of it `torch` behind `sentence-transformers`. It does not fit, so this
deployment uses `requirements-slim.txt`: **149 MB installed**, no torch.

Compass then falls back to `LexicalBackend` — cosine over token counts plus
character 4-grams. That is a real similarity measure, not a stub, but it cannot
tell that "built dashboards" and "developed reporting" are the same claim.

Two things get worse:

- **JD match scores read lower and less fairly.** Measured on one fixture: 36.7
  with the model, 27.5 without, for identical input.
- **The quality gate's divergence signal is less accurate.** This is the one that
  matters — comparing a new cover letter against your recent ones is how the gate
  catches templated work, and that is the feature the whole tool exists for.

The app is honest about it rather than quietly approximate: every score carries
its backend name, `semantic_backend_is_model` is false in the report, match
reports show a **lexical fallback** pill, and Settings says so outright. Nothing
presents a lexical score as a semantic one.

**Verified on the slim build**, running from a venv with torch,
sentence-transformers, transformers, numpy, scipy and scikit-learn all absent:
every page returns 200, DOCX and PDF export work, and the ATS check, JD scoring
and quality gate all run.

## 1. Create the service

1. Sign up at [render.com](https://render.com) with GitHub. No card.
2. **New → Blueprint**, pick `mor64ph/ai-jobsearch-engine`.
   Render reads `render.yaml` at the repo root and configures everything:
   the slim Dockerfile, the free plan, the Singapore region, the health check,
   and a generated `COMPASS_SECRET_KEY`.
3. **Apply**. First build is 5–10 minutes.

If Blueprint gives you trouble, the manual equivalent is **New → Web Service →**
pick the repo, Runtime **Docker**, Dockerfile path
`./deploy/render/Dockerfile`, plan **Free**, health check `/login`.

## 2. Add your Gemini key

`render.yaml` marks it `sync: false`, so Render will not invent one — you add it
after the first deploy.

Service → **Environment** → **Add Environment Variable**:

```
GEMINI_API_KEY = <your key>
```

Get one free at [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
Without it the deterministic half still works — ATS checks, JD scoring, the
quality gate, the tracker and discovery never called a model — and only the LLM
features report as unconfigured.

`COMPASS_SECRET_KEY` is already generated by Render and never shown to anyone.
Compass refuses to start with its shipped placeholder when bound publicly, which
is why it must be a real value.

## 3. Check it

Your URL is `https://compass-<something>.onrender.com`.

```
[ ] Sign-in page shows the demo credentials
[ ] They work and land on a populated dashboard
[ ] Settings reports the lexical fallback  <- expected here, not a fault
[ ] Résumés shows a variant with an ATS score
[ ] Applications lists three at different stages
[ ] Discover -> add board `fivetran` (Greenhouse) -> Rank
[ ] Open it on your phone
```

The Discover step is the one worth doing. It exercises ATS ingestion, the
deterministic scorer and the ranking pipeline in one click — and it still works
here, because only the semantic half of scoring was lost.

## Operating notes

**It sleeps after 15 minutes idle** and cold-starts in 30–60 seconds. A visitor
arriving at a sleeping service waits, with no indication of why. This is the
single worst thing about the free tier for a portfolio link.

**Data resets on every deploy and every wake.** No persistent disk on free.
`COMPASS_DEMO_MODE` re-seeds a populated demo each time, which is what makes
that survivable — every visitor gets a clean, working instance rather than an
empty one.

**750 instance-hours a month** across all free services. One service sleeping
when idle stays well inside it.

**Gemini's free tier is 20 requests per day per model**, shared by every visitor
because it is one key. A demo that gets attention will exhaust it; everything
deterministic keeps working.
